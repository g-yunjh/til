### 1. 도커를 알아야 하는 이유
- 파드, 컨테이너, 도커, 쿠버네티스의 관계  
	- 쿠버네티스는 컨테이너 오케스트레이션 도구이고, 파드는 하나 이상의 컨테이너를 감싸는 최소 단위입니다.  
	- 컨테이너 기술의 대표주자가 **도커(Docker)**이고, 쿠버네티스가 컨테이너를 관리할 때 주로 도커를 사용해왔습니다.  
	- 최근에는 도커 대신 컨테이너 런타임으로 containerd, cri-o 등이 사용되지만, 기본적인 컨테이너 구조는 도커를 통해 학습하면 이해가 쉽습니다.

- 다양한 컨테이너 관리 도구  
	- **도커(Docker)**: 가장 많이 쓰이는 컨테이너 도구로, 이미지 생성·배포·실행 기능을 제공합니다.  
	- **Podman**: 도커와 유사한 CLI를 가진 도구로, 데몬리스(daemonless) 방식으로 동작합니다.  
	- **containerd**: 경량화된 컨테이너 런타임으로, 쿠버네티스의 표준 인터페이스인 CRI(Container Runtime Interface)를 지원합니다.  
	- 이 외에도 LXC, rkt 등의 컨테이너 기술이 있으나, 도커를 중심으로 학습하는 것이 쿠버네티스 사용에 가장 도움이 됩니다.

### 2. 도커로 컨테이너 다루기
- 컨테이너 이미지 알아보기  
	- 컨테이너는 이미지를 기반으로 실행되며, 이미지는 실행 환경과 애플리케이션을 함께 포함하고 있습니다.  
	- `docker images` 명령어로 현재 로컬에 저장된 이미지를 확인할 수 있습니다.

- 컨테이너 실행하기  
	- `docker run` 명령어로 컨테이너를 실행할 수 있습니다.  
	- 예:  
	```bash
	docker run --name mynginx -d -p 8080:80 nginx
	```

- 컨테이너 내부 파일 변경하기  
	- `docker exec -it <컨테이너 이름> bash` 명령어로 컨테이너 내부에 접속할 수 있습니다.  
	- 내부 파일을 편집하거나 명령어를 실행할 수 있습니다.

- 사용하지 않는 컨테이너 정리하기  
	- `docker ps -a`로 모든 컨테이너를 확인하고, `docker rm`으로 중지된 컨테이너를 삭제할 수 있습니다.  
	- `docker system prune` 명령어로 한꺼번에 불필요한 리소스를 정리할 수 있습니다.

### 3. 4가지 방법으로 컨테이너 이미지 만들기
- 기본 방법으로 빌드하기  
	- `Dockerfile`을 작성해 이미지를 빌드합니다.  
	- 예:  
	```bash
	docker build -t myapp:latest .
	```

- 컨테이너 용량 줄이기  
	- 멀티스테이지 빌드나 최소한의 베이스 이미지 사용으로 이미지 용량을 최적화합니다.  
	- 예를 들어 `alpine` 베이스 이미지를 사용하면 용량이 대폭 줄어듭니다.

- 컨테이너 내부에서 컨테이너 빌드하기  
	- **Docker-in-Docker** 또는 **BuildKit**을 사용해 컨테이너 내부에서 이미지를 빌드할 수 있습니다.  
	- CI/CD 환경에서 유용합니다.

- 최적화해 컨테이너 빌드하기  
	- 빌드 캐시를 활용하거나 레이어 수를 최소화해 빌드 속도와 이미지 크기를 최적화합니다.  
	- 필요 없는 파일은 `.dockerignore`에 지정해 빌드 시 제외합니다.

### 4. 쿠버네티스에서 직접 만든 컨테이너 사용하기
- 쿠버네티스에서 도커 이미지 구동하기  
	- `kubectl`과 YAML 스펙에서 `image` 항목을 직접 만든 도커 이미지로 지정해 파드를 배포할 수 있습니다.  
	- 예:  
	```yaml
	containers:
	  - name: myapp
	    image: myrepo/myapp:latest
	```

- 레지스트리 구성하기  
	- 이미지를 쿠버네티스에서 사용하려면, **도커 허브**나 **자체 프라이빗 레지스트리**에 이미지를 푸시해야 합니다.  
	- 프라이빗 레지스트리 사용 시, `imagePullSecrets`로 인증 정보를 설정할 수 있습니다.

- 직접 만든 이미지로 컨테이너 구동하기  
	- 로컬 클러스터(minikube 등)에서는 `minikube docker-env`를 활용해 로컬 이미지를 직접 사용하기도 합니다.  
	- 운영 환경에서는 레지스트리에 이미지를 업로드한 뒤, `kubectl apply`로 YAML을 배포해 파드를 실행합니다.
