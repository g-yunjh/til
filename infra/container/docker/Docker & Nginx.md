## Docker

* **컨테이너 기반 가상화 기술**
  애플리케이션과 실행 환경(라이브러리, 의존성 등)을 하나의 **이미지**로 묶어, 일관된 환경에서 실행할 수 있도록 해줌.
* **가상머신(VM)과의 차이**

  * VM은 하이퍼바이저 위에 운영체제를 올려 실행 → 무겁고 느림
  * Docker는 **호스트 OS의 커널을 공유** → 가볍고 빠름
  * VM은 수 GB 단위, Docker 이미지는 수 MB 단위인 경우가 많음
* **장점**

  * 환경 불일치 문제 해결 (개발 환경 = 배포 환경)
  * 가볍고 빠른 실행 속도
  * 배포 자동화 및 확장성 (쿠버네티스와 잘 맞음)
  * 커뮤니티와 생태계가 매우 활발 (공식 이미지, 오픈소스 이미지 활용 가능)

---

### Docker CLI 명령어

* `docker run`: 새로운 컨테이너 실행 (이미지가 없으면 자동으로 pull)
* `docker ps`: 실행 중인 컨테이너 목록 확인

  * `docker ps -a`: 종료된 컨테이너 포함 전체 확인
* `docker stop <id>`: 컨테이너 종료
* `docker rm <id>`: 종료된 컨테이너 삭제
* `docker exec -it <id> bash`: 실행 중인 컨테이너 내부 터미널 접속
* `docker logs <id>`: 로그 출력
* `docker images`: 로컬에 있는 이미지 목록 확인
* `docker pull <이미지명>`: Docker Hub 등 레지스트리에서 이미지 다운로드

👉 CLI는 단일 컨테이너 제어에 유용하지만, 다중 컨테이너 관리에는 한계 → Docker Compose 필요

### Dockerfile

* 이미지를 빌드하기 위한 **설정 파일**
* 애플리케이션 실행에 필요한 **환경 정의**

자주 쓰이는 명령어:

* `FROM`: 기반 이미지 지정 (예: `node:18-alpine`)
* `RUN`: 명령어 실행 (패키지 설치 등)
* `COPY`/`ADD`: 파일 복사
* `CMD`: 컨테이너 시작 시 실행할 기본 명령 (한 번만 작성 가능)
* `ENTRYPOINT`: 컨테이너 실행 시 항상 실행할 명령 (CMD와 함께 쓰이면 CMD는 인자로 전달)
* `WORKDIR`: 작업 디렉토리 설정
* `ENV`: 환경 변수 설정
* `HEALTHCHECK`: 컨테이너 상태 확인 명령

👉 `Dockerfile`은 **재현 가능한 환경**을 만드는 핵심 요소

## Docker Compose

* **여러 컨테이너를 코드로 정의하고 동시에 실행/관리**하는 도구
* 단일 명령(`docker-compose up`)으로 컨테이너를 띄울 수 있음
* 주로 `docker-compose.yml` 파일에 설정

자주 쓰이는 속성:

* `image`: 사용할 이미지 이름
* `build`: Dockerfile로부터 이미지 빌드
* `command`: 컨테이너 시작 시 실행할 명령어 지정
* `ports`: 호스트 ↔ 컨테이너 포트 매핑
* `volumes`: 데이터/설정 파일 공유
* `environment`: 환경 변수 설정
* `depends_on`: 실행 순서 제어 (예: DB → App)
* `restart`: 컨테이너 재시작 정책
* `networks`: 컨테이너 간 네트워크 설정

👉 Compose는 작은 프로젝트나 로컬 개발 환경에서 유용, 운영 환경에서는 주로 **쿠버네티스** 같은 오케스트레이션 도구로 확장

## Nginx

* **고성능 웹 서버 & 리버스 프록시 서버**
* 아파치(Apache)보다 가볍고 빠르며, 높은 동시 접속 처리에 강점

### 주요 역할

* **Reverse Proxy**

  * 클라이언트 요청을 받아 백엔드 서버로 전달
  * 보안, 로드 밸런싱, 캐싱, SSL 종료(HTTPS) 등 다양한 기능 제공
* **Load Balancing**

  * 여러 백엔드 서버에 트래픽을 분산
  * 라운드 로빈(Round Robin), 최소 연결(Least Connections), IP 해시(IP Hash) 등 알고리즘 지원

### 추가 기능

* 정적 파일 제공 (HTML, CSS, JS)
* 캐싱 및 압축으로 성능 최적화
* SSL/TLS 인증서 적용 (HTTPS 지원)
* 다양한 모듈 확장 가능

👉 실제 서비스 운영에서 **웹 서버 + 프록시 서버 + 보안 게이트웨이** 역할을 함께 수행
