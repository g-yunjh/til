### 1. 컨테이너 인프라 환경에서 CI/CD
- CI/CD 도구 비교  
	- **Jenkins**: 플러그인 기반으로 확장이 자유롭고, 다양한 언어·빌드 도구를 지원합니다. 쿠버네티스 플러그인으로 쿠버네티스에 파드 기반 에이전트를 띄울 수 있습니다.  
	- **GitLab CI**: GitLab과 통합돼 있어 소스코드 변경 → 빌드/배포가 자연스럽게 연결됩니다.  
	- **Argo CD**: 쿠버네티스 전용 GitOps 도구로, Git 저장소를 단일 소스로 삼아 선언적인 배포를 자동으로 동기화합니다.  
	- **Tekton**: 쿠버네티스 네이티브 CI/CD 파이프라인을 관리하는 도구로, Pod 단위의 Task를 선언적으로 정의합니다.

- 젠킨스로 쿠버네티스 운영 환경 개선하기  
	- 젠킨스는 플러그인을 통해 쿠버네티스 클러스터와 쉽게 통합됩니다.  
	- **Kubernetes Plugin**을 사용하면 빌드·배포 파이프라인마다 독립적인 Pod 에이전트를 동적으로 생성하고, 빌드가 끝나면 파드를 자동으로 제거해 자원을 절약합니다.  
	- GitOps와 연계하거나 Helm, Kustomize를 활용해 지속적으로 업데이트되는 쿠버네티스 환경을 운영할 수 있습니다.

### 2. 젠킨스 설치를 위한 간편화 도구 살펴보기
- 배포 간편화 도구 비교하기  
	- **kubectl apply**: YAML을 직접 선언해 배포. 가장 기본적이지만, 환경별 관리가 불편할 수 있습니다.  
	- **Kustomize**: `kustomization.yaml`을 기반으로 오버레이 방식으로 리소스를 관리해, 환경별 배포 YAML을 쉽게 관리할 수 있습니다.  
	- **Helm**: 패키지(Chart) 형태로 리소스를 배포. 복잡한 배포 구성(Secret, ConfigMap, Deployment 등)을 하나의 Helm 차트로 관리합니다.

- 커스터마이즈로 배포 간편화하기  
	- 디렉토리 구조 예시:  
	```
	base/
	  deployment.yaml
	  service.yaml
	  kustomization.yaml
	overlays/
	  dev/
	    kustomization.yaml
	    configmap.yaml
	  prod/
	    kustomization.yaml
	    configmap.yaml
	```
	- `kustomization.yaml` 예시:  
	```yaml
	resources:
	  - ../../base
	patchesStrategicMerge:
	  - configmap.yaml
	```
	- `kubectl apply -k overlays/dev`로 환경별 배포를 손쉽게 할 수 있습니다.

- 헬름으로 배포 간편화하기  
	- **Helm 차트**는 `values.yaml` 파일로 환경별 설정을 분리합니다.  
	- 설치 명령어 예시:  
	```bash
	helm repo add jenkins https://charts.jenkins.io
	helm repo update
	helm install jenkins jenkins/jenkins -f values.yaml
	```
	- `helm upgrade`로 변경 사항을 쉽게 반영할 수 있습니다.

### 3. 젠킨스 설치 및 설정하기
- 헬름으로 젠킨스 설치하기  
	- 예시 명령어:  
	```bash
	helm install jenkins jenkins/jenkins --namespace jenkins --create-namespace \
	  --set controller.adminUser=admin \
	  --set controller.adminPassword=admin \
	  --set controller.serviceType=LoadBalancer
	```
	- 설치가 완료되면 `kubectl get svc -n jenkins`로 외부 IP를 확인해 접속할 수 있습니다.

- 젠킨스 살펴보기  
	- 웹 대시보드에서 Job 생성, 파이프라인 모니터링, 빌드 기록을 관리할 수 있습니다.  
	- 파이프라인 설정을 직접 UI에서 작성하거나, Git에서 Jenkinsfile을 가져오도록 구성할 수 있습니다.

- 젠킨스 컨트롤러 설정하기  
	- `values.yaml`에서 리소스 설정 예시:  
	```yaml
	controller:
	  resources:
	    requests:
	      cpu: "500m"
	      memory: "1Gi"
	    limits:
	      cpu: "1"
	      memory: "2Gi"
	```
	- 필요 플러그인 목록을 `values.yaml`에서 미리 정의해 자동 설치할 수 있습니다.

- 젠킨스 에이전트 설정하기  
	- 쿠버네티스 플러그인을 활성화하고, PodTemplate을 생성해 빌드 파드를 정의합니다.  
	- 예시 PodTemplate YAML:  
	```yaml
	kind: Pod
	metadata:
	  labels:
	    jenkins: agent
	spec:
	  containers:
	  - name: jnlp
	    image: jenkins/inbound-agent:latest
	  - name: maven
	    image: maven:3.8.4
	```
	- 빌드 시마다 새로운 Pod가 생성돼 자원을 효율적으로 사용합니다.

### 4. 젠킨스로 CI/CD 구현하기
- Freestyle로 간단히 echo-ip 배포하기  
	- Freestyle Job을 생성 후, **Build 단계**에서 Shell 명령어:  
	```bash
	kubectl apply -f echo-ip.yaml
	```
	- echo-ip는 단순한 Nginx 기반 테스트 앱으로, 배포 상태를 쉽게 확인할 수 있습니다.

- Pipeline 프로젝트로 손쉽게 echo-ip 배포하기  
	- Jenkinsfile 예시:  
	```groovy
	pipeline {
	  agent any
	  stages {
	    stage('Clone') {
	      steps {
	        git 'https://github.com/myrepo/echo-ip'
	      }
	    }
	    stage('Deploy') {
	      steps {
	        sh 'kubectl apply -f echo-ip.yaml'
	      }
	    }
	  }
	}
	```
	- GitHub의 `echo-ip.yaml`을 가져와 자동으로 배포됩니다.

- Pipeline 프로젝트로 구현하는 블루그린 배포 전략  
	- Jenkinsfile에서 Blue/Green 환경을 나눠서 배포 후, 트래픽을 새 환경으로 전환합니다.  
	- 예시 단계:  
	  1️⃣ Blue 환경에 신규 버전 배포  
	  2️⃣ 트래픽을 Green에서 Blue로 전환  
	  3️⃣ Green 환경 정리  
	- 실시간 롤백도 가능해 무중단 배포를 구현할 수 있습니다.

### 5. 젠킨스 플러그인을 통해 구현되는 GitOps
- 쿠버네티스 환경에 적합한 선언적인 배포 환경  
	- GitOps 방식으로 Git을 소스로 삼아, 쿠버네티스의 실제 상태를 Git과 일치시키는 방식으로 운영합니다.  
	- Jenkins의 **Pipeline**과 **Git 플러그인**을 사용해 Git의 변경 사항을 자동으로 감지합니다.

- 슬랙을 통해 변경 사항 알리기  
	- **Slack Notification 플러그인**을 사용해 빌드 성공/실패 시 Slack 채널에 알림을 전송할 수 있습니다.  
	- Jenkinsfile 예시:  
	```groovy
	slackSend(channel: '#deployments', message: "배포 완료! 상태: ${currentBuild.currentResult}")
	```

- 배포 변경 사항을 자동 비교하기  
	- Git의 선언적 YAML과 실제 쿠버네티스 리소스를 `kubectl diff`나 Argo CD를 통해 자동 비교합니다.  
	- Jenkins와 Argo CD를 연계해, Jenkins는 빌드/테스트를 담당하고 Argo CD가 최종 배포 상태를 유지하도록 연동할 수 있습니다.

💡 **팁:**  
- Jenkins 파이프라인에서 Helm, Kustomize 명령어도 사용할 수 있어, YAML 관리까지 자동화할 수 있어요.  
- GitOps를 제대로 구현하고 싶다면 Argo CD와 연계하는 구조도 함께 고민해보세요.
