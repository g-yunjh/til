- 왜 쿠버네티스일까
	- 쿠버네티스는 **컨테이너 오케스트레이션**을 위한 솔루션으로, 컨테이너화된 애플리케이션의 배포, 확장, 관리 등을 자동화할 수 있게 해줍니다.
	- **오케스트레이션**이란 복잡한 단계들을 관리하고 요소들을 유기적으로 연결해 손쉽게 운영되도록 돕는 과정입니다.
	- 대부분의 IT 기업들은 마이크로서비스 아키텍처를 채택하면서, 쿠버네티스를 활용해 인프라를 효율적으로 운영하고 있습니다.

- 쿠버네티스 구성 방법
	- **관리형 쿠버네티스**: AWS EKS, Azure AKS, Google GKE 등 클라우드에서 쿠버네티스 클러스터를 손쉽게 사용할 수 있도록 관리해주는 서비스입니다.
	- **설치형 쿠버네티스**: Red Hat OpenShift, SUSE Rancher 같은 솔루션을 사용하여 직접 인프라에 설치·운영합니다. 대부분 상용 솔루션으로, 기능이 풍부하지만 비용이 발생합니다.
	- **구성형 쿠버네티스**: `kubeadm` 등의 오픈소스 도구를 이용해 직접 쿠버네티스를 구성하고 관리하는 방식입니다. 관리와 유지보수 부담이 있지만, 유연성과 비용 측면에서 이점이 있습니다.

- 쿠버네티스 구성하기
	- 쿠버네티스 클러스터를 구성하려면 마스터 노드와 워커 노드를 준비하고, `kubeadm` 같은 도구를 사용해 클러스터를 초기화해야 합니다.
	- 클러스터를 구성한 뒤, `kubectl` 명령어로 클러스터를 관리합니다.

- 파드 배포를 중심으로 쿠버네티스 구성 요소 살펴보기
	- 쿠버네티스의 핵심 단위는 **파드(Pod)** 입니다. 파드는 하나 이상의 컨테이너로 이루어진 논리적 단위로, 쿠버네티스가 배포·운영하는 최소 단위입니다.
	- 파드, 노드, 서비스, 컨트롤러 등 주요 오브젝트들이 함께 상호작용하면서 안정적으로 애플리케이션을 실행합니다.

- 파드의 생명주기로 쿠버네티스 구성 요소 살펴보기
	- 파드는 생성 → 준비 상태(Ready) → 실행 상태(Running) → 완료(Completed) / 실패(Failed) 순으로 상태가 변화합니다.
	- 이 과정에서 ReplicaSet, Deployment, Scheduler, Controller Manager 등의 쿠버네티스 구성 요소가 파드의 생명주기를 관리·감시합니다.

- 쿠버네티스 구성 요소의 기능 검증하기
	- `kubectl get` 명령어로 오브젝트 상태를 확인하거나, `kubectl describe`로 상세 정보를 살펴볼 수 있습니다.
	- `kubectl logs`나 `kubectl exec`를 통해 파드 내부의 컨테이너 로그와 실행 상태를 확인해 기능을 검증할 수 있습니다.
